# DEMO_PLAN — статические демо двух проектов (PORTFOLIO-DEMOS-005)

Демо собираются как автономные статические подпапки портфолио: `/ershdesign/` и `/prota/`.
Исходники (`~/dev/ershdesign`, `~/dev/prota`) — только источник визуала и логики интерфейса,
читаются read-only. Все данные в демо вымышлены и сгенерированы для демонстрации.

---

## 1. ershdesign — кабинет проекта дизайн-студии

**Что это.** Node/Express + EJS + SQLite. Сайт студии и закрытый кабинет проекта:
клиент входит по шестизначному коду, команда — по логину и паролю. Внутри — прогресс
по стадиям проектирования, задачи, файлы, рабочая документация (листы), график платежей,
чаты (клиентский / командный / личный) и админ-панель управления проектом.

**Визуальный стиль (из `public/css/main.css`).** Тёмная тема: фон `#0d0d0c`,
поверхность `#111110`, текст `#f4f2ee`, акцент — золото `#c9a87c`, служебные оливковый
и терракота. Шрифты: Unbounded (display, uppercase, letter-spacing −0.04em),
Onest (текст), Bad Script (логотип-скрипт). Радиус 6px, тонкие линии
`rgba(244,242,238,.14)`, нумерованные секции («05 — Стадии проектирования»).

**Ролевая модель (подтверждена `src/lib/auth.js`, миграция `010_team_roles.sql`).**
Роли `owner` / `member` / `client` — переключатель «Смотреть как» в демо соответствует
исходнику. Владелец видит админ-панель целиком (Проекты, Финансы, Команда, Портфолио,
Заявки), сотрудник — только Этапы/Задачи/Файлы, клиент — кабинет проекта, финансы и
единственный клиентский чат без списка переписок (`singleClientChat` в `chats/index.ejs`).

**Выбранные экраны (5).**
1. **Вход по коду проекта** — шесть PIN-ячеек, поле ФИО, подсказка демо-кода.
2. **Кабинет проекта** — дашборд (прогресс, ближайший срок, открытые задачи, команда),
   шкала стадий, задачи, файлы с чипами-фильтрами, таблица листов рабочей документации.
3. **Финансы проекта** — стоимость / оплачено / остаток + график платежей.
4. **Чаты** — список переписок, лента с группировкой сообщений одного автора,
   отправка сообщения (добавляется локально).
5. **Админ-панель** — боковые вкладки с нумерацией и счётчиками, KPI-плитки,
   карточки «Этапы проекта» и «Последние заявки», таблицы этапов/задач/файлов.

**Нужные мок-данные.** Проект «Квартира на Лесной», код 486 210; 6 стадий; 8 задач
со статусами; 6 файлов трёх разделов; 6 листов документации; 4 платежа; 3 чата и
~14 сообщений; 4 заявки; команда из 4 вымышленных людей (Анна М., Сергей К. и т.п.).

## 2. PROTA — платформа управления проектами дизайн-студии

**Что это.** Next.js 15 (App Router) + Prisma/SQLite. Студийное рабочее пространство:
картотека проектов, внутри проекта — восемь вкладок (Обзор, Концепция, Файлы,
Комплектация, ТЗ подрядчикам, Календарь, Финансы, Аналитика), сквозной мессенджер
в выезжающей панели, заметки, уведомления. Права — через abilities, отдельный
короткий набор разделов для кабинета заказчика (`CLIENT_SECTIONS`).

**Визуальный стиль (из `src/app/globals.css` и CSS-модулей).** Светлая тема,
`--radius: 0` (острые углы везде), тонкие линии вместо теней, единственный шрифт
DM Sans. Палитра: чернила `#171717`, серый `#f5f5f5`, линия `#e8e8e8`, акценты —
лайм `#d1ff4d` и оранжевый `#ff6a2c`. Каркас: шапка 56px, левая полоса разделов 52px
(активный пункт — чёрный квадрат с лаймовой иконкой), на ≤860px полоса уезжает в
нижнюю панель. Узнаваемая деталь — «картотека»: проект как папка с цветным ярлыком
(лайм / оранжевый при просрочке) и полоской этапов.

**Выбранные экраны (4).**
1. **Картотека проектов** — сводка студии (KPI, ближайшие события, загрузка команды)
   и три вида списка: Картотека / Список / Карточки, переключаются сегментами.
2. **Проект → Обзор** — шапка с крошками и лентой вкладок, карточки: заказчик,
   этапы, задачи с чекбоксами, исходные данные, лента изменений.
3. **Проект → Комплектация** — таблица позиций по помещениям с итогами по бюджету,
   статусами и реакциями клиента (согласовано / заменить).
4. **Мессенджер** — выезжающая справа панель: список переписок + лента, отправка
   сообщения (добавляется локально).

**Нужные мок-данные.** 5 проектов (код, объект, площадь, город, бюджет, этап, сроки,
команда); по активному проекту — 6 этапов, 7 задач, 5 блоков исходных данных,
6 записей ленты; 12 позиций комплектации по 4 помещениям; 4 переписки и ~12 сообщений;
6 вымышленных сотрудников с инициалами.

## Общие правила сборки

- `index.html` + `css/` + `js/` + `data/` в каждой папке, все пути относительные (`./…`).
- Переключение экранов, вкладок, видов, открытие карточек и отправка сообщений —
  клиентский JS поверх мок-JSON, состояние только в памяти страницы (без localStorage,
  без бэкенда, без внешних библиотек).
- На каждом экране — фиксированная плашка «Демо-версия · данные вымышлены»
  и ссылка «← Портфолио» на `/`.
- Реальные данные, файлы, БД, ключи и контакты из исходников не переносятся;
  перед коммитом — grep-проверка собранных папок.
